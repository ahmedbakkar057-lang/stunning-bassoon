# ملفات نشر MS VPS على Railway

هذه الحزمة جاهزة للرفع إلى GitHub ثم ربطها بخدمة Railway، أو لفك ضغطها ورفع محتوياتها إلى مستودع جديد.

## طريقة الاستخدام

1. فك ضغط الملف بحيث يكون `Dockerfile` و`panel.py` في جذر المشروع نفسه.
2. اربط مستودع GitHub بالمشروع في Railway.
3. Railway سيكتشف `Dockerfile` ويبدأ البناء تلقائيًا.
4. لا تضبط `PORT` يدويًا؛ التطبيق يقرأ قيمة `PORT` التي توفرها Railway.
5. بعد نجاح النشر افتح `/login` على الدومين العام.

## متغيرات Railway

| المتغير | القيمة/الاستخدام |
|---|---|
| `BASE_PATH` | اتركه `/data` عند ربط Volume. |
| `RUN_BOT` | `0` افتراضيًا، أو `1` لتشغيل بوت Telegram داخل الخدمة. |
| `PANEL_BOT_API_TOKEN` | توكن API عند استخدام توفير الحسابات عبر البوت. |
| `PANEL_URL` | الدومين العام للوحة، اختياري. |
| `SESSION_COOKIE_SECURE` | `1` مع HTTPS، وهو الوضع المناسب لـ Railway. |

## Volume مهم جدًا

Railway قد يعيد إنشاء الحاوية، لذلك أضف Volume للخدمة واربطه بالمسار:

```text
/data
```

بدون Volume ستعمل اللوحة، لكن بيانات المستخدمين والإعدادات والملفات قد تضيع عند إعادة النشر أو إعادة التشغيل.

## فحص البناء

- ملف `Dockerfile` يثبت الاعتماديات أثناء البناء.
- ملف `railway.toml` يحدد Health Check على `/login`.
- ملف `Procfile` موجود كخطة احتياطية، لكنه لا يغيّر استخدام Dockerfile.
- لا توجد أسرار أو ملفات بيانات تشغيل داخل الحزمة.

## تشغيل الملفات واستخراج ZIP

- تم تفعيل تشغيل الملفات من داخل حساب المستخدم، ومنها `index.js`، وتحتوي صورة Docker على Node.js وnpm.
- عند استخراج ZIP من اللوحة، يتم وضع محتوياته في **نفس مجلد ملف ZIP** بدل إنشاء مجلد إضافي باسم `_extracted`.
- ما زالت حماية المسارات وامتدادات الرفع والأوامر الخطيرة فعالة.

## ملاحظة عن البورتات

Railway يوفّر بورت HTTP عامًا واحدًا عبر `PORT`. البورتات الإضافية داخل اللوحة ليست عامة تلقائيًا على Railway.
